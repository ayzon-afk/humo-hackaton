# Как писать код, чтобы AI-проверка не нашла проблем

AI-ревьюер обычно смотрит на одно и то же: **структура, читаемость, безопасность, обработка ошибок, тесты, документация, консистентность**.
Проект уже соответствует всему ниже — главное, не сломать это завтра в спешке.

## 0. Одна команда перед каждым деплоем

```bash
npm run check   # ESLint + Prettier + 21 тест + сборка. Красное — не деплоим.
```

## 1. Структура

- Один файл — одна ответственность. Компонент > ~150 строк или делает две вещи → разбить.
- Страница (`views/`) только собирает компоненты и вызывает store/api. Логика — в `composables/`, `stores/`, `services/`.
- Новое кладём рядом с похожим: компонент записей → `components/items/`, правило агента → `server/src/agent/rules.js`.
- Всё, что меняется под тему, — в `client/src/config/*` или `.env`, не в разметке.

## 2. Именование

- Компоненты — `PascalCase.vue` (`ItemForm.vue`), composables — `useSomething.js`, api — `somethingApi`.
- Функции — глаголом (`loadReports`, `changeStatus`), булевы — `is/has/can` (`canRun`, `isAdmin`).
- Без сокращений (`description`, а не `desc`), без `data1`, `temp`, `test2`.
- Константы-справочники — `UPPER_CASE` в начале файла (`MESSAGES`, `ACTIONS`).

## 3. Vue

- Только `<script setup>` + Composition API. Пропсы с типами, `defineModel` для v-model.
- `v-for` всегда с `:key` по id, не по индексу (кроме статичных списков).
- Не мутировать пропсы. Эмитить события (`emit('status', item, next)`).
- Подписки на socket/scroll/keydown — снимать в `onBeforeUnmount`.
- Асинхронные действия: `loading` → `try/catch` → `push(e.message, 'error')` → `finally`.

## 4. Сервер

- Каждый `POST/PATCH` — через `validate(schema)` (zod в `validation/schemas.js`). Никаких `if (!req.body.x)` в роутах.
- Роутер тонкий: принять → вызвать сервис → вернуть JSON. Логика — в `services/` или `agent/`.
- Ошибки — `throw Object.assign(new Error('Понятный текст'), { status: 400 })`, их ловит `errorHandler`.
- Права — `requireAuth`, `requireRole('admin')`. Пароли/хеши никогда не уходят в ответ (`publicUser`).
- Секреты — только из `process.env` через `config.js`. Ни одного ключа в коде.

## 5. Тесты

- Новая серверная логика → тест в `server/tests/` (Vitest + Supertest).
- Минимум на фичу: «работает в нормальном случае» + «отклоняет плохие данные/без прав».
- Тесты используют временную базу (`tests/setup.js`) и не трогают реальные данные.

## 6. Стиль и UI

- Цвета, отступы, радиусы — только `var(--…)` из `tokens.css`. Никаких `#hex` и `px` «на глаз» в компонентах.
- Доступность: у кнопок-иконок `aria-label`, у полей — `label`, у декоративных иконок `aria-hidden="true"`.
- Тексты интерфейса — русский, кнопки — глаголом. Ошибка = что случилось + что сделать.

## 7. Комментарии и документация

- Комментарий объясняет **зачем**, а не что: `// фокус сразу в первое поле`, а не `// ставим фокус`.
- У каждого модуля сверху — одна строка, что он делает (JSDoc `/** … */`).
- Нет закомментированного кода, `console.log` для отладки, `TODO` без смысла.
- Новая фича → строчка в README (возможности) и в нужном файле `kit/`.

## 8. Git

- Коммиты по-английски, в повелительном наклонении: `Add revenue alert to agent`, `Fix empty state on map page`.
- Один коммит — одна логическая правка. `npm run deploy -- "сообщение"` делает коммит с твоим текстом.

## ❌ Красные флаги для AI-ревьюера (не допускать)

| Флаг                                                                   | Вместо этого               |
| ---------------------------------------------------------------------- | -------------------------- |
| Ключ/пароль в коде                                                     | `process.env` + `.env`     |
| `any`-валидация, `req.body` без схемы                                  | zod-схема                  |
| Огромный компонент на 400 строк                                        | разбить на 3–5 компонентов |
| Скопированный 3 раза кусок кода                                        | функция/компонент          |
| `catch {}` без обработки там, где пользователь должен узнать об ошибке | тост с понятным текстом    |
| Неиспользуемые импорты, переменные, файлы                              | `npm run lint` их найдёт   |
| Разный стиль кавычек/отступов                                          | `npm run format`           |
| Инлайн-стили с цветами                                                 | классы и токены            |
| Мёртвые кнопки, которые ничего не делают                               | убрать или доделать        |
